# Week 6 관찰

## Task 1 · Link State by Hand

- 최단 경로 비용이 같으면 출발 라우터에서의 첫 홉 이름이 사전순으로 앞서는 경로를 고릅니다. 실제 라우터는 구현별 tie-break를 쓰거나 ECMP로 여러 같은 비용 경로를 함께 사용할 수 있습니다.
- `u`에서 `w`의 다음 홉은 `x`입니다. `u-w` 직접 링크 비용 5보다 `u-x-y-w`의 총 비용 3이 더 낮기 때문입니다.
- `u-x`가 끊기면 `w`, `x`, `y`, `z`의 다음 홉은 `v`로 바뀌고, `v`는 계속 `v`를 사용합니다.

## Task 2 · Break a Real Network and Time the Repair

- 세 경로는 모두 기숙사 네트워크를 유지한 채 측정했습니다. 국내 경로의 첫 공인 IP 홉은 `39.127.66.1`이지만, 숫자 주소만으로 캠퍼스 경계라고 단정할 수는 없습니다. `1.1.1.1`은 13홉·약 9ms로 도달해 가까운 지역 anycast 복제본을 시사합니다.
- `www.stanford.edu`는 `stanford.netlifyglobalcdn.com` CDN 주소로 연결되어 15홉·7–13ms였고, 해저 케이블에 해당하는 100ms 지연 점프는 보이지 않았습니다. `*`는 중간 라우터가 TTL 초과 ICMP를 억제하거나 방화벽이 응답을 필터링할 때 나타날 수 있습니다.
- OSPF 표에서 r1은 직접 연결되지 않은 `172.20.0.0/16`을 배웠습니다. 링크 단절 후 r1의 표는 1.89초, r2의 이웃 제거는 32.68초(기본 Dead 40초), 복구는 3.4초(Hello 10초), 비용 변경은 1.044초였습니다. 복구는 Hello를 받으면 시작되지만 장애 감지는 Dead 타이머를 기다립니다.

## Task 3 · Reconverge Without Recomputing the World

- 라우터는 최단 거리와 선택된 SPF 트리의 부모를 함께 보관합니다. 이는 추가 O(V) 메모리를 쓰고, 그래프 저장 공간 O(E)에 비하면 작습니다.
- 선택 트리 링크가 끊기거나 비용이 변하면 전체 SPF를 하고, 트리 밖 링크 제거/비용 증가와 더 짧아지지 않는 추가·할인은 건너뜁니다. 1,000 이벤트에서 테이블은 매번 맞았고 SPF 실행을 64% 줄였습니다.
- 이번 Python 벤치마크에서 증분 구현의 벽시계 시간은 기준선보다 느렸지만, 라우터에서는 이벤트마다 네트워크 전체를 재계산하는 CPU 부담을 줄이는 것이 중요합니다. 이 시뮬레이터의 Python 오버헤드만으로 실제 라우터의 적합성을 판단할 수 없습니다.
