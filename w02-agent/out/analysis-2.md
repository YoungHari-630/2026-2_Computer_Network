## How the problem changed from HTTP/1.1 to HTTP/3

HTTP/1.1 defines reusable, correctly framed textual request/response exchanges, but its pipelined responses remain ordered (RFC 9112, Sections 2.1, 6, 7.1, and 9.3.2). HTTP/2 adds binary framing, independent application streams, and field compression on one TCP connection, improving concurrency and reducing repeated metadata; TCP packet loss can nevertheless block the whole connection (RFC 9113, Sections 1–2). HTTP/3 moves stream reliability and multiplexing into QUIC so unrelated streams can continue after loss and uses QPACK for field compression, while accepting that UDP blocking can force fallback to a TCP-based HTTP version (RFC 9114, Sections 1.1–3.1).
