# Week 7 관찰

## Task 1 · 학습 스위치

- 입력 포트로 프레임을 되돌리면 같은 링크에서 프레임이 중복되고, 루프가 있는 토폴로지에서는 복제 프레임이 계속 증폭되어 브로드캐스트 스톰이 날 수 있습니다. 목적지 MAC을 모르는 스위치는 해당 LAN 안에서 목적지를 찾으려고 플러딩하지만, 라우터는 다른 네트워크로 보내는 경로가 없으면 IP 패킷을 버립니다.
- 엔트리는 마지막 관측 후 300초가 지나면 만료되며, 이 방식은 조용한 호스트의 유효한 위치 정보까지 잃을 수 있습니다. 링크 다운이나 호스트 이동 알림처럼 더 직접적인 신호가 있으면 즉시 지울 수 있지만, 일반 Ethernet 호스트의 침묵만으로는 연결 해제를 정확히 알기 어렵습니다.

## Task 2 · ARP 관찰

- ARP 표는 삭제 전 9개, 이후 8개 항목이었습니다(1개 감소). 캐시 삭제 직후 캡처에서 `192.168.0.40`이 내 PC(`192.168.0.39`)를 찾는 요청이 가장 먼저 보였고, 이 요청의 송신 MAC을 학습해 .40이 먼저 다시 나타났습니다. 게이트웨이 `192.168.0.1`을 찾는 요청·응답은 약 5.6초 뒤에 보였습니다.
- 게이트웨이 요청의 Ethernet 목적지는 브로드캐스트 `ff:ff:ff:ff:ff:ff`, 응답 목적지는 내 MAC `30:e3:a4:49:88:42`였습니다. 약 139초 캡처에 요청 16개와 응답 16개가 있었고 첫 60초에는 총 14개 프레임이었습니다(캠퍼스 장치 수가 N이면 단순 환산은 분당 약 `14×N`개); 원격 웹 서버 자체는 ARP 대상이 아니며 게이트웨이의 MAC만 필요합니다.

## Task 3 · 용량이 제한된 스위치

- 최소 사용 빈도 엔트리를 내보내고 동률이면 가장 오래 미사용한 엔트리를 내보냈습니다. 각 MAC의 관측 빈도를 유지하고, 새 MAC은 빈 테이블에 넣거나 최저 빈도보다 더 많이 관측됐을 때만 입장시켰으며 후보 기록은 4×용량으로 제한했습니다.
- 벤치마크에서 admission 제어와 빈도 기반 퇴출로 낭비 전달이 323,380에서 161,000으로 50% 줄었고 미전달은 0건이었습니다. 공격자는 임의 MAC을 계속 출발지로 보내 테이블을 채우고 진짜 목적지 프레임을 플러딩하게 만들 수 있으며, 포트 보안·MAC 학습 제한과 스푸핑 방지가 완화책입니다.
